## Findings

### F-1 | minor | A-01, A-19

**What.** The comment says the stopped test's code "can never reach the new page". That holds only while the leftover code is waiting on a browser call. Leftover code that waits on anything else (a timer, a file, a network call) makes its next call on the *new* shared page.

**Both attempts needed an edit to a test.** A-01 inserts one timer wait into one paint-only test. A-19 adds a new test. The unedited suite is **not** exposed: I read every `await` in the shared-page tests of `visual.e2e.ts` at `9106b94`; each one is a call on the page. During the swap, `page` names the closed page until the new one is assigned, so those calls throw. A-05, A-12, A-27, A-31 and A-36 confirm this by run. The finding is a false general statement plus an unguarded trap for the next person who edits the file. That is why it is minor and not major.

**Repro: exact steps.**
1. `git checkout 9106b9492241cb00007bcb0847037f6d58d895eb`; `npm ci --ignore-scripts`; `export PW_CHROMIUM=$HOME/.cache/ms-playwright/chromium-1255/chrome-linux64/chrome`.

**Reproductions.** A-19: 3/3. A-01 command A: 2/3. A-01 command B: 3/3.

**Why it matters.**
- Definition (d): `visual.e2e.ts` lines 53 to 55 ("can never reach the new page"), pull request #5 point 3 ("never reaches the new page"), and ISO-03 ("stops the old test's code at its next browser call") state as general what holds under a condition they do not name.
